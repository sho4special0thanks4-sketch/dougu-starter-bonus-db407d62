# 完成の確認チェックリスト

『リフォーム営業13年の私が、Claude Codeで作った道具』読者特典。「できました」と言う前に確かめることです。

## 1. 自分で動かす（使う端末で、実際に押す）

- [ ] 使う端末（iPad・スマホ・事務所のパソコン）で、実際にボタンを押した。パソコンで動いただけで終わりにしていない。
- [ ] 数の欄に、0・空欄・マイナス・とても大きい数を入れて、表示が壊れない。
- [ ] 印刷（またはPDF）をして、文字が切れたり、ページがずれたりしていない。
- [ ] 「保存がない状態（初めて開く）」の、開いた直後の画面を見た。
- [ ] 「保存がある状態（前回の続き）」の、開いた直後の画面を見た。別のお客様の入力が出ていない。

## 2. 数字を確かめる（式の外で）

- [ ] 計算のある所を1か所、電卓で計算し直して、画面と合う。
- [ ] 公式の数字（補助額・期限・金利など）を、公式ページと1つずつ見比べた。
- [ ] 数字や制度に、出典と確認日が付いている。古くなる情報に「〇年〇月時点」と書いてある。
- [ ] 「概算です」「目安です」「最終判断は窓口・専門家で」の注意が、画面と印刷の両方にある。

## 3. 別の目で見てもらう

- [ ] 作った会話とは別の新しい会話で、「ゼロから疑って、おかしい所を全部挙げて」と頼んだ。
- [ ] 重大・中・軽微に分けてもらい、重大から順に直した。
- [ ] できれば、人にも見てもらった（遠慮なく言ってくれる人）。
- [ ] AIの指摘が正しいかを、自分の目でも確かめた。

## 4. 「確認した」に、何を見たかを添える

- [ ] AIの報告に「何をどこで見たか」が書いてある。書いていないものは、確認していないものとして扱った。
- [ ] 「未確認」と書かれたものは、確認する手段がないか考え、あれば自分で確かめた。
- [ ] 自分の報告にも、「見たもの」と「見られなかったもの」を分けて書いた。

## 5. 直して、記録して、育てる

- [ ] 直したことを、1行ずつ記録した（例: 「○月○日、数の欄に0が入ると壊れた → 1以上だけ受け付けるように直した」）。
- [ ] 数で確かめられることは、検算テスト（回帰テスト）にして、直すたびに走らせている。
- [ ] 年度や制度が変わったときに差し替える所（表・期限・金額）を、メモしてある。
- [ ] 公開・配布するものは、ロゴやURLなど、会社のものが残っていないか、もう一度見た。
